# Session: 20260408-1943

## Request
Fix the 4 critical issues documented in CLAUDE.md: ffmpeg resource explosion (1074% CPU on 120x480@10fps), GUI independence (display survives close), process lifecycle (no orphan zombies), and general efficiency (15.7% idle CPU).

## Team
Kru-direct. Single pipeline touching ambilight.py, device.py, gui.py — too coupled for agents.

## Changes

### ambilight.py
- `_start_decoder()`: added `-nostdin`, `-threads 1` (limits h264 decoding to one core), `-stream_loop -1` for loop mode (ffmpeg handles looping internally instead of rapid Python restarts)
- `decode_loop`: fallback restart now sleeps 0.5s between attempts instead of immediate restart
- `AmbilightThread`: switched from `threading.Lock` + `time.sleep(0.1)` polling to `threading.Event`-based wakeup. Idle: 1 wakeup/sec vs 10/sec. Active: instant wakeup on new frame
- `stop()`: sets event to wake thread for immediate exit
- Finally block: checks `lcd._keep_display` before calling `led.off()`

### device.py
- Added `_keep_display = False` to `LCDDevice.__init__`
- `play_h264()`: only sends CMD_STOP_PLAY if `_keep_display` is False

### gui.py
- `do_close_request()`: sets `lcd._keep_display = True` before requesting stop
- Waits for play thread to finish (up to 5s) so ffmpeg cleanup runs
- No longer calls `led.off()` — LEDs persist at last color
- No longer calls `lcd.stop_play()` indirectly — device keeps displaying content

## Root Cause Analysis

1. **CPU explosion**: ffmpeg h264 decoder used all available cores by default (`-threads` unset). For a 120x480@10fps stream, all 16+ cores maxed out decoding a trivial resolution. Additionally, when looping short clips, Python rapidly killed and restarted ffmpeg processes with no delay
2. **GUI killing display**: `do_close_request` called `request_stop()` → `play_h264()` called `stop_play()` → device cleared display. Also called `led.off()` → LEDs went dark
3. **Orphan processes**: daemon threads die on process exit but subprocess children survive. `do_close_request` didn't wait for the play thread to run its cleanup (which terminates ffmpeg)
4. **Idle CPU**: AmbilightThread polled at 10Hz even with no new frames. Event-based approach sleeps until data arrives
